# 기록 연결 · 0.3.0

0.4.0에서 네이버 CalDAV 읽기 시험 연결을 추가했다. 설정된 로컬 서버에서 캘린더를 고르고 하루 한 번 가져올 수 있는 흐름이며, 실제 계정 호환성은 미검증이다. [네이버 설정 안내](NAVER.md)를 먼저 확인한다. 아래 파일 가져오기 기능은 그대로 유지한다.

## 사용 순서

1. 하단 **기록 → 기록 연결**을 연다.
2. 회고·기록 화면에 표시할 종류를 선택한다. 선택을 해제해도 저장된 데이터는 삭제되지 않는다.
3. ICS, 사진 또는 CSV를 선택한다. 앱은 사용자가 선택한 파일만 기기 안에서 읽는다.
4. 가져오기 미리보기에서 추가·중복·제외 수와 날짜를 확인한다. 저장 전까지 현재 데이터는 변경되지 않는다.
5. 기록 화면에서 종류·날짜·내용으로 찾거나, 홈의 **작년 이맘때**를 연다.

## 캘린더

- UTF-8 ICS, 최대 2MB, 5,000개 일정. UID·DTSTART·SUMMARY가 필요하다.
- 종일 및 시간 지정 일정의 **원래 캘린더 시작일**로 기록한다. 시간대 변환, 시간순 배치, 기간 전체 날짜 전개는 하지 않는다.
- `RRULE`, `RDATE`, `EXDATE`, `RECURRENCE-ID`가 있는 반복·예외 일정, 취소 일정은 제외하고 개수를 알려준다. 전체가 제외되면 적용하지 않는다.
- 잘못된 날짜·필수 항목 누락·중복 UID는 파일 전체를 거부한다. 외부 파일의 알림·첨부·링크를 실행하거나 자동으로 접속하지 않는다.
- UID로 중복을 판별한다. 재가져오기는 기존 편집 내용을 덮어쓰지 않는다. 외부의 변경·삭제를 동기화하는 기능은 아니다.
- Google·iCloud·네이버 계정 로그인이나 주기적 동기화는 현재 구현되지 않았다.

## 사진

- JPEG·PNG·WebP, 한 번에 10장, 장당 최대 15MB. HEIC와 동영상은 미지원이다.
- JPEG의 EXIF `DateTimeOriginal`을 우선 사용한다. 없으면 파일명의 `YYYYMMDD`, `YYYY-MM-DD`, `YYYY_MM_DD`를 제안한다.
- 촬영일을 확인하지 못했으면 날짜를 비워 둔다. 파일 수정일을 촬영일로 사용하지 않는다. 사용자가 날짜를 정해야 저장된다.
- 미리보기에서 날짜를 고칠 수 있다. 날짜의 근거(촬영일·파일명·직접 선택)를 표시한다.
- 파일 바이트 해시로 같은 사진을 구분한다. 파일 내용이 바뀌면 별도 사진으로 취급될 수 있다.
- 원본을 최대 800px의 JPEG 축소본으로 변환해 브라우저에 보관한다. 투명 영역은 흰색으로 변환한다. 원본 파일은 변경하지 않는다.
- 원본 EXIF/GPS 메타데이터는 저장하지 않는다. 선택하지 않은 사진이나 전체 사진 보관함에는 접근하지 않는다.

## 가계부

- UTF-8 CSV, 최대 2MB, 5,000행. 헤더는 `date,title,amount`로 고정한다.
- 날짜는 `YYYY-MM-DD`, 금액은 **원 단위 양의 정수 지출**이다. 입금·잔액·외화·은행별 원본 CSV 형식은 미지원이다.
- 같은 날짜·제목·금액과 파일 내 동일 행의 등장 횟수로 ID를 생성한다. 같은 파일을 다시 가져와도 중복되지 않는다.
- 서로 다른 파일의 동일한 거래가 같은 항목으로 간주될 수 있다. 중복 개수를 미리 확인한다. 거래 취소·수정·은행별 거래 식별자 처리는 아직 없다.
- 은행 아이디·비밀번호·인증서 등을 받지 않으며 금융기관에 접근하지 않는다. 직접 지출을 남길 수도 있다.

```csv
date,title,amount
2025-11-23,커피,4500
2025-11-24,"점심, 간식",12000
```

## 일기와 외부 정보

- 기존 한 줄 기록을 일기로 유지한다. 작성·수정·검색·날짜 이동·삭제가 가능하다.
- 외부 일기 서비스 자동 연동·서비스별 내보내기 변환은 아직 제공하지 않는다.
- 그 무렵의 세상에는 직접 확인한 날씨·사건·뉴스의 제목, 날짜, 메모, 출처 이름, HTTP(S) 링크를 남긴다. 출처 링크를 자동으로 열거나 기사를 수집·요약하지 않는다.
- 기록이 해당 지역의 실제 날씨를 의미한다고 추론하지 않는다. 자동 데이터가 필요하면 날짜뿐 아니라 당시 지역과 출처 기준도 정해야 한다.

## 저장과 백업

기존 `imamttae:v1` 저장 키를 유지하고 `memories`, `categories`를 추가했다. 기존 일정·일기는 그대로 읽으며 새 필드가 없으면 빈 통합 기록과 전체 종류 표시로 시작한다.

사진 축소본은 현재 localStorage에 저장해 브라우저 공간을 사용한다. 복수 기기 자동 동기화·암호화 보관은 제공하지 않는다. 가져오기·수정·복원은 저장 성공 후에만 적용하고, 저장 공간 오류가 나면 기존 데이터를 유지한다. 사진이 많아지면 IndexedDB 등으로의 저장소 이전이 필요하다.

설정의 새 JSON 백업은 **버전 2**로 통합 기록과 사진 축소본을 포함한다. 버전 1 백업도 읽는다. 복원은 새 항목만 추가하고 현재 테마·표시 종류·편집 내용을 유지한다. 버전 2 백업은 구버전 앱에서 복원할 수 없다.

## 자동 연동을 위한 다음 작업

현재 파일 가져오기 UI를 계정 자동 연동처럼 표시하지 않는다. 다음 구현에는 지원할 캘린더 서비스, 모바일 플랫폼, 계정·서버 구조를 먼저 결정해야 한다.

- 캘린더: 읽기 권한, OAuth 앱 등록·동의 화면·허용된 리디렉션, 연결 해제, 토큰 보관, 증분 갱신과 반복 일정 전개.
- 사진: 운영체제별 사진 선택·보관함 권한과 백그라운드 제약, 원본 보관 여부, 기기 변경·삭제 정책.
- 금융: 직접 연동/제휴 범위와 자격·보안 요건을 확인한 후 진행. 일반 계정 연동과 동일하게 취급하지 않는다.
- 외부 자료: 날짜·지역 기준, 이용 가능한 데이터/API, 저작권·재배포 범위, 기사 출처와 발생일·보도일 구분.

Google Calendar의 경우 읽기 범위와 캘린더 목록 범위를 기능에 맞게 최소화해야 한다. OAuth 앱 등록 없이 동작하는 연결 버튼을 만들지 않는다. [Google 공식 권한 안내](https://developers.google.com/workspace/calendar/api/auth)
