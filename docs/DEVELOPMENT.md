# 구현 현황과 다음 작업

## 0.4.1 · 로컬 연결 설정 도구

- `npm run setup:naver`: 직접 연 터미널에서 비밀번호를 화면에 표시하지 않고 입력한다. 파이프·명령 인수로 비밀번호를 받지 않는다.
- 기존 네이버 설정은 기본적으로 보존하며 `--replace`를 명시할 때만 교체한다. 다른 환경 변수·주석·여러 줄 값과 줄바꿈을 보존한다.
- 임시 파일에 작성하고 기존 파일 변경 여부를 확인한 뒤 반영한다. 충돌·입력 취소 시 기존 설정을 유지한다.
- `npm run check:naver`: 인증·캘린더 목록 조회의 성공 여부와 개수만 출력한다. 아이디·비밀번호·일정 내용은 출력하지 않는다. `--offline`은 설정 유무만 확인한다.
- 자동 테스트 24개를 통과했다. 설정 도구는 가상 값과 임시 폴더에서 검증했고, 실제 `.env`는 만들지 않았다.
- 현재 실제 네이버 설정이 없어 실계정 검증은 남아 있다. 사용자가 자신의 터미널에서 설정해야 한다.

## 0.4.0 · 네이버 캘린더 읽기 시험 연결 (이전 버전)

- 첫 자동 연동 대상으로 네이버 캘린더를 선택했다. 공식 공개 API의 일정 등록 기능과 과거 기록 조회를 구분하고 CalDAV 읽기 어댑터를 추가했다.
- 로컬 서버의 `.env`에서 네이버 ID와 전용 앱 비밀번호를 받는다. 브라우저와 백업에는 자격 증명을 저장하지 않는다.
- 캘린더 목록 발견·선택, 전년 같은 날짜 전후 14일 조회와 중복 없는 추가를 구현했다.
- 사용자가 켠 경우 앱을 열 때 하루 한 번 가져온다. 기본값은 꺼짐이며 서버 백그라운드 예약이나 양방향 동기화는 아니다.
- 읽기 메서드만 사용하고 대상 HTTPS 호스트를 고정했다. 리다이렉트·외부 호스트·DTD/ENTITY를 거부하고 응답·요청 크기와 조회 시간을 제한한다.
- 로컬 API는 동일 출처와 전용 헤더를 검사한다. 미설정·인증 실패·조회 실패·저장 실패를 구분해 안내한다.
- `fast-xml-parser`와 lockfile을 도입했다. 실행 전 `npm ci`가 필요하다.
- 자동 테스트 20개와 Chrome 가상 서버 검증을 통과했다. 실제 네이버 계정은 사용하지 않았으며 실서버 호환성 검증은 남아 있다.

## 0.3.0 · 날짜별 통합 기록 (이전 버전)

- 캘린더·사진·가계부·일기·그 무렵의 세상 중 표시할 종류를 고른다. 선택 해제는 데이터를 삭제하지 않는다.
- 기록 화면을 날짜별 타임라인으로 확장했다. 검색과 종류 필터를 함께 적용한다.
- ICS 일정과 표준 CSV 지출을 파일에서 가져온다. 반복·취소 제외와 중복 개수를 미리 알리고 적용 전에 확인한다.
- 선택한 사진의 EXIF 촬영일 또는 파일명 날짜를 제안한다. 날짜가 없으면 직접 지정한다. 최대 800px 축소본만 저장한다.
- 일기 외에 지출과 날씨·기사 출처 링크를 직접 기록할 수 있다. 가져온 일정·사진·지출·외부 출처를 수정·삭제할 수 있다.
- 홈에서 작년 같은 날짜 전후 7일의 선택한 기록을 회고하고 기간별 타임라인을 연다. 윤년 2월 29일은 전년 2월 말일을 기준으로 삼는다.
- 기존 저장 키·일정·일기를 유지한다. 버전 2 백업에 사진까지 포함하며 버전 1도 복원한다.
- 새 데이터와 가져오기는 저장 성공 후에만 적용한다. 동일 원본 사진과 같은 UID의 일정은 재가져오기 시 중복되지 않는다.
- 계정 자동 동기화·은행 연동·실시간/과거 날씨 자동 조회·뉴스 수집은 미구현이다. 외부 자료는 사용자가 출처와 함께 직접 남긴다.

검증: 자동 테스트 15개와 Chrome 기능 검증. ICS·CSV·사진 파일 선택, 가져오기 취소/중복, 날짜 없는 사진 저장 방지, 종류 선택 후 재시작, 출처 링크, 작년 회고, 버전 1·2 백업과 기존 편집·검색·달력·320px 화면을 확인한다.

## 0.2.0 · 생활 기록 기능 보강 (이전 버전)

- 일정 제목을 눌러 내용·날짜를 수정한다. 항목 ID와 완료 여부는 유지한다.
- 기록 카드의 연필 버튼으로 글·날짜를 수정한다. 작성 중 글자 수를 표시한다.
- 기록 화면에서 내용·날짜로 검색하고 결과 수를 확인한다. 검색어를 지우면 전체 목록으로 돌아간다.
- 홈에 완료한 할 일 수와 얇은 진행 표시를 추가했다. 캐릭터와 기존 메뉴 배치는 유지했다.
- 달력에서 월을 이동하면 선택 날짜도 해당 월로 이동한다. 말일은 도착 월에 존재하는 마지막 날로 보정한다.
- 설정에서 JSON 백업 가져오기를 지원한다. 0.1.0의 버전 1 백업과 호환된다.
- 파일은 10MB까지 지원한다. 파일 형식·버전·유효 날짜·필수 항목·중복 ID를 검사하며 일부만 조용히 누락하지 않는다.
- 적용 전에 신규 일정·기록과 이미 있는 항목 수를 보여준다. 취소하거나 파일이 잘못되면 현재 데이터를 변경하지 않는다.
- 복원은 새 ID만 추가하며 현재 항목·완료 상태·테마를 보존한다. 같은 백업을 반복 복원해도 중복 추가하지 않는다. 내용을 기준으로 한 중복 제거·충돌 병합은 제공하지 않는다.
- 복원은 브라우저 저장이 성공한 뒤에만 메모리 상태를 변경한다. 저장 실패 시 오류를 안내하고 재시도할 수 있다.

검증: 자동 테스트 8개와 Chrome 기능 검증을 제공한다. 실제 파일 선택, 복원 미리보기·취소·반복 복원·잘못된 파일 거부, 저장 공간 오류 후 재시도, 일정·기록 내용과 날짜 변경, 완료 상태 유지, 검색, 새로고침 후 저장 유지, 사계절 테마, 320px 화면을 확인한다.

## 0.1.0 · 2026-11-23 첫 구현 (이전 버전)

비어 있던 저장소에 의존성 없는 HTML/CSS/JavaScript 웹앱을 구성했다. `npm start`로 실행한다. 실제 화면은 반응형이고 홈의 캐릭터와 콘텐츠가 계절에 따라 바뀐다.

- 오늘 할 일 작성·완료·삭제, 계절 이야기 열기와 일정으로 담기.
- 달력 월 이동·날짜 선택·날짜별 데이터 표시.
- 글 기록 추가·삭제, 실제 작년 같은 날짜의 기록 다시 보기.
- 브라우저 localStorage 저장, 손상된 데이터 구조 정리, 저장 실패 안내.
- 12개월 테마 선택과 자동 모드, 사계절 이미지 4종, 월별 문구 12종.
- JSON 백업 내려받기. 가져오기 기능은 미구현.
- 키보드 접근, 모션 감소, HTML 이스케이프, 내부 파일 접근을 차단하는 개발 서버.

## 검증

- `npm run check`: JavaScript 문법 검사.
- `npm test`: 계절 경계, 윤년 달력, 데이터 검증, 서버 파일 노출 제한.
- `npm run test:browser`: Chrome에서 모바일 너비, 일정 완료·지속 저장, 기록 HTML 이스케이프, 새로고침 후 기록 유지, 달력 월 이동과 날짜별 일정, 사계절 미리보기, 런타임 오류 확인. 모바일 사계절·데스크톱 스크린샷 생성.

첫 구현 검증 결과: 문법 검사, 자동 테스트 4개, 실제 Chrome 기능 검증을 모두 통과했다. 오늘·달력·기록은 320px 너비에서도 가로 넘침이 없었다. [실제 홈 화면](home-current.png)은 검증 시점의 화면이다.

## 콘텐츠 관리

현 콘텐츠는 짧은 편집 예시다. 지역·기상 조건에 따른 자동 추천이 아니며 정량적 성능이나 의학적 효과를 주장하지 않는다. 전통 원리의 설명을 본격적으로 확장할 때 공식 문화·과학 기관의 출처와 검토 날짜를 콘텐츠 데이터에 추가한다. 현재는 실시간 날씨·절기 날짜·제철 지역 정보 등을 임의로 계산해 표시하지 않는다.

## 확장할 여덟 분야

| 분야 | 향후 내용 | 필요한 준비 |
|---|---|---|
| 절기·계절 | 절기, 계절 변화 | 연도별 기준 데이터와 출처 |
| 생활 관리 | 환기, 세탁, 냉난방 | 상황별 콘텐츠·반복 일정 |
| 제철 음식 | 식재료와 보관 정보 | 지역 차이·식품 안전 검토 |
| 전통 지혜 | 관찰, 재료, 원리 | 사실·속설 구분과 공식 출처 |
| 여행·자연 | 계절 풍경과 행사 | 지역 설정·갱신·취소 반영 |
| 추억·기록 | 사진, 지난 기록 | 이미지 저장·백업·동기화 |
| 행정·지원 | 신청 기간·마감 | 대상 조건·출처·만료 처리 |
| 식물 관리 | 식물별 관리 | 식물 종류·환경에 따른 조건 |

첫 화면을 분야별 메뉴로 가득 채우지 않는다. 관심 분야를 선택하고 관련 정보가 날짜로 모이는 구조를 유지한다.

## 출시 전 순서

1. 실제 사용자와 오늘 → 담기 → 실천 → 기록 흐름을 검증하고 월별 콘텐츠를 준비한다.
2. 반복 일정, 백업 충돌 병합과 데이터 이전 방식을 설계한다. 기본 백업 가져오기와 편집은 0.2.0에 구현했다.
3. 계정·동기화가 필요하면 인증, 서버, 개인정보 처리와 삭제 정책을 함께 설계한다.
4. 사진·위치·날씨·알림은 각 기능이 동작할 때 필요한 권한만 요청한다.
5. Android/iOS 또는 PWA 출시 방식을 결정하고 실기기·접근성·저장 안정성을 점검한다.

네이티브 패키징, 서비스 워커와 오프라인 캐시, 스토어 등록, 배포 자동화는 현재 포함되지 않는다.
