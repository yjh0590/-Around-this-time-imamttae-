# 네이버 캘린더 시험 연결 · 0.4.1

사용자가 첫 연동 대상으로 **네이버 캘린더**를 선택했다. 이 문서는 개인용 로컬 서버의 읽기 전용 시험 연결을 설명한다. 다중 사용자 서비스의 출시 설계가 아니다.

## 확인한 공식 지원 범위

네이버의 공개 Calendar API 문서는 일정 등록을 제공한다. 기존 기록을 읽는 경로로는 공식 고객센터의 CalDAV 설정을 참고했다. 고객센터는 iOS 설정과 Mac 읽기 지원, Android 미지원 등의 조건을 안내한다. **현재 Node 서버 연결이 네이버가 보증하는 앱 통합이라는 의미는 아니다.** 실제 계정으로 검증하기 전까지 시험 기능으로 표시한다.

- [공개 일정 등록 API](https://developers.naver.com/docs/login/calendar-api/calendar-api.md)
- [네이버 공식 CalDAV 안내](https://help.naver.com/service/5620/contents/2426)
- [애플리케이션 비밀번호 안내](https://help.naver.com/service/5640/contents/8584)
- 확인일: 2026-11-23.

## 로컬 설정

1. Node.js 20.12 이상에서 `npm ci`로 의존성을 설치한다. 브라우저 검증은 Node.js 22 이상이 필요하다.
2. 네이버 보안 설정에서 이 연결에 쓸 애플리케이션 비밀번호를 생성한다. 공식 안내의 계정별 지원 조건을 확인한다.
3. 직접 연 터미널에서 `npm run setup:naver`를 실행한다. 아이디와 비밀번호를 입력하며 **비밀번호는 화면에 표시되지 않는다.** 기존 네이버 설정이 있으면 교체하지 않고 종료한다. 필요한 경우에만 `npm run setup:naver -- --replace`로 교체한다. 다른 환경 변수와 주석은 보존한다.
4. `npm run check:naver`로 네이버 인증과 캘린더 목록 조회를 확인한다. 결과는 성공 여부와 캘린더 개수만 출력하며 아이디·비밀번호·캘린더 이름·일정을 출력하지 않는다. 실제 네이버에 접속하지 않고 설정 유무만 확인하려면 `npm run check:naver -- --offline`을 사용한다.

직접 파일을 편집하려면 `.env.example`을 `.env`로 복사하되 기존 `.env`는 덮어쓰지 않는다. 파일에 필요한 값은 다음과 같다. **이 파일이나 비밀번호를 채팅·이슈·GitHub에 올리지 않는다.**

```dotenv
NAVER_CALDAV_USERNAME=여기에_네이버_아이디
NAVER_CALDAV_APP_PASSWORD=여기에_전용_애플리케이션_비밀번호
```

5. 서버를 다시 시작한다: `npm start`.
6. 앱의 **기록 → 기록 연결 → 네이버 캘린더 · 시험 연결**에서 목록을 확인하고 가져올 캘린더를 선택한다.
7. **지금 가져오기**로 결과를 확인한다. 원하면 **앱을 열 때 하루 한 번 자동으로 가져오기**를 켠다. 기본값은 꺼짐이다.

설정 도구는 비밀번호를 명령 인수나 파이프로 받지 않는다. 입력 중 설정 파일이 변경되면 덮어쓰지 않고 종료한다. Ctrl+C 또는 입력 종료로 취소하면 저장하지 않는다.

이 구현에서 `.env`는 암호화 파일이 아닌 개인 기기의 서버 설정이다. 클라이언트에 자격 증명을 반환하지 않으며 `.gitignore`로 제외한다. 공용 컴퓨터·인터넷 공개 서버·다중 사용자 서비스에 그대로 사용하지 않는다. 제품 출시에 필요한 사용자별 인증·안전한 자격 증명 보관·연결 해제 설계는 별도 작업이다.

## 실제 동작 범위

- 네이버 계정 경로와 캘린더 목록을 발견하고 사용자가 선택한 최대 10개 캘린더를 조회한다.
- 기준은 **사용자 브라우저 날짜의 전년 같은 날짜 전후 14일**이다. 회고 홈의 기본 요약은 그중 전후 7일을 표시한다.
- 캘린더 시작일 기준의 일정 스냅샷을 추가한다. 반복·취소 일정은 현재 ICS 파서의 지원 범위에 따라 제외하고 개수를 알린다.
- 같은 캘린더·UID는 재가져와도 중복되지 않는다. 사용자가 편집한 내용이 우선이며 원본 변경·삭제를 자동 반영하지 않는다.
- 자동 가져오기는 브라우저를 열거나 다시 활성화했을 때 하루 한 번 실행한다. 앱을 닫은 동안의 백그라운드 수집이나 서버 예약 작업은 아니다.
- 저장이 성공한 경우만 마지막 확인 날짜를 갱신한다. 자동 실패는 같은 페이지 세션에서 반복 재시도하지 않으며 수동 재시도할 수 있다.
- 자동 옵션을 끄면 다음 자동 조회가 중단된다. 이미 시작한 조회나 저장된 기록은 삭제하지 않는다. 인증을 완전히 해제하려면 서버 설정의 두 값을 제거하고 서버를 재시작한 뒤 네이버에서 해당 앱 비밀번호를 폐기한다.

## 구현 경계

- `naver-caldav.mjs`는 `PROPFIND`·`REPORT`만 사용한다. 일정 쓰기·수정·삭제 요청을 보내지 않는다. 앱 비밀번호 자체가 읽기 전용 권한으로 제한되는 토큰이라는 뜻은 아니다.
- 네이버 CalDAV의 고정 HTTPS 호스트만 허용한다. 서버가 반환한 다른 호스트·인증 포함 URL·리다이렉트로 자격 증명을 전송하지 않는다.
- 응답 크기·연결 시간을 제한하고 DTD/ENTITY가 포함된 XML을 거부한다.
- 로컬 API는 동일 출처, 전용 요청 헤더, JSON POST를 확인한다. 자격 증명은 응답·브라우저 저장·백업에 포함하지 않는다.
- 선택한 캘린더의 해시 ID와 자동 옵션만 브라우저에 보관한다. 다른 백업을 복원해 자동 조회가 새로 켜지지 않는다.
- 네이버웍스 API나 네이버 로그인으로 계정의 과거 일정을 읽을 수 있다고 가정하지 않는다.

## 검증 상태

자동 테스트와 Chrome 검증에서 **가상 CalDAV/XML 응답과 가상 계정**을 사용했다. 목록 발견, 선택 조회, 중복 방지, 하루 한 번 자동 가져오기, 인증 실패·리다이렉트 거부, 동일 출처 제한과 기존 기록 기능을 확인했다.

**실제 네이버 계정·실서버 호환성은 아직 검증하지 않았다.** 계정 자격 증명이 설정되어 있지 않아 이 검증은 남아 있다. 실제 연결이 지원되지 않거나 실패하면 기존 ICS 파일 가져오기를 계속 사용할 수 있다.

[가상 응답으로 검증한 설정 화면](naver-connection-demo.png). 실제 계정 연결의 증거가 아닌 UI 검증용 화면이다.

구현 표준: [CalDAV RFC 4791](https://www.rfc-editor.org/rfc/rfc4791.html). XML 파서는 버전을 고정한 `fast-xml-parser`를 사용한다.
